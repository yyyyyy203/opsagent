## 1. 产品目标与完成口径

交付供单一可信操作者长期使用的本地多项目只读巡检系统。正常安装与启动后，用户能选择模拟 Target，手动或定时发起调查，看到有证据的结论和缺失项，审核并复用知识，处理站内巡检结果；服务重启、来源异常和数据恢复有明确行为。

分三种状态报告成熟度，不使用笼统的“全部完成”：

1. **本地工程闭环通过**：S1、S2、S3 离线部分、S4、S5、S6 全部满足确定性验收；所有遥测为模拟数据。
2. **本地诊断可用通过**：再完成 S3 真实模型有界验收和人工复核。未运行或失败时只能保留第一种状态。
3. **对外或生产使用**：不属于本 Spec；还需身份授权、部署边界、真实业务 Profile 和环境容量验收。不能从前两种状态推导第三种状态。

只读是指不改变被监测业务；本地保存配置、审核记录、任务和报告属于应用自身写入，须经过类型校验、并发控制和审计。

盘点基线：分支 `codex/event-message-v2`、提交 `bdfb20e`，工作区干净。以下为源码与文档核对，本次没有重跑产品测试。

## 3. 范围、非目标与架构边界

本计划涉及 bootstrap 组装、application 用例、API/Web、模拟适配器和运维基础设施。新增调度与结果管理只调用已有 Target 用例，不创建第二套 Agent 主循环。所有具体存储、来源、Clock、ID、定时器和模型在 bootstrap 注入。

始终使用本地模拟指标和日志，不启动或修改 `group-buy-market`。真实模型请求作为独立 opt-in 验收；默认测试无在线模型、LangSmith 或业务系统请求。不新增真实动作，不改变工具执行管线、HITL 或记忆晋级资格。

非目标：公网/团队部署、SSO/RBAC、真实告警 Webhook、邮件/即时通信外发、分布式调度、多进程高可用、完整 Trace/发布变更平台、生产业务接入、自动修复、强制引入向量库。外发通知与 Webhook 在授权及网络边界清楚后另立方案；本版用站内通知实现结果可见。

## 4. S1：普通宿主 Target 接线

### 4.1 配置与启动

- 新增可选 `AGENTOPS_TARGET_CONFIG`，值为显式绝对文件路径；配置版本从 `schemaVersion: 1` 开始。无配置时保留旧 simulation 行为，不静默创建 Target。
- 复用 Catalog、连接注册与 Profile 校验器；文件引用既有身份、部署世代、场景、指标映射、来源连接 ID、记忆策略及预算。凭据只引用服务端安全配置，不放入 Catalog DTO、事件、错误正文或模型输入。
- 配置中的相对资源引用只相对配置文件目录解析，并校验允许根；不依赖 cwd。重复身份、未知场景、非法预算或凭据引用缺失导致明确启动失败；短暂来源不可达在运行时以来源状态/部分诊断呈现，不能伪造可用证据。
- 首版修改配置需重启，不做隐式热加载。历史 Run 保留启动快照；新 Run 使用新配置；恢复按现有当前策略门校验，不能用新配置覆盖历史快照。
- 保持 loopback 监听和既有 Origin 边界；普通宿主不得启用测试时钟、故障控制、任意模型替换等测试管理接口。

### 4.2 执行组装

在 bootstrap 构造 Resolver、Starter、OperationPolicy、RuntimeProvider 与来源分区，复用同一持久化 bundle。正式 OperationPolicy 校验当前 Target、能力与策略，禁止复制夹具“全部允许”的策略。

Metrics 优先复用 `target-metrics-subagent.ts`；Logs 需核对并补 Target snapshot/scope 绑定、父子归属和来源分区，不能仅换 profileId 复用全局 simulation 状态。两个 Target 可以使用不同指标映射、阈值、日志过滤和预算。

一次正常启动支持 A/B 两个模拟 Target、Metrics+Logs、手动运行、历史/证据回查、取消及允许的重启恢复。保留 legacy simulation 入口，跨 Target 或 legacy 入口不得读取或操作 Target 资源。

## 5. S2：受治理知识进入实际运行

复用 `createTargetKnowledgeManagementService`、SQLite 知识存储和 `MemoryCoordinator`；通过既有 `AgentMemoryHarness.coordinator` 路径注入。若公开组装端口不足，先记录最小兼容扩展，不将核心绑到 SQLite。

- 能力、审核来源、发布上下文和只读 Procedural capability registry 均由宿主可信配置提供。
- 同一 Target 完成 Semantic 与 Procedural 的创建、审核、发布、召回；Episodic 保持 observation→人工批准的既有语义。模拟案例不晋级真实业务经验。
- 检查模型实际输入中的知识 ID、版本和来源标记，不能只用“UI 有记录”证明召回。知识是历史参考，不能冒充本轮采集的事实或给出动作授权。
- 未审核、撤销、到期、作用域错误、版本/digest 不一致的知识不进入新 Run；恢复与运行中重校验遵循已有冻结选择语义，不偷偷扩大检索。
- 必需知识不可用按既有准入/资格规则阻塞或标记缺口；可选知识失败明确降级。存储失败、超时和 Abort 可观察，不无限重试。
- 记忆开关关闭时，已有无记忆诊断仍可使用。三个记忆类型共享预算，不能因接线新增重复注入。

## 6. S3：场景与诊断质量

### 6.1 最小模拟场景集

在 Profile/场景模块扩展能力，不在 Harness 硬编码业务规则：

| 场景族 | 最少对照 | 断言重点 |
| --- | --- | --- |
| 失败率 | 正常、超阈值、低样本 | 数值/分母/阈值确定性；低样本不高置信归因 |
| 延迟 | 正常、p95 升高 | 单位、窗口、直方图或来源计算方式明确 |
| 流量 | 正常、相对基线下降 | 基线与当前窗口对齐；无基线标缺失 |
| 依赖异常 | 上游错误与依赖日志关联、仅时间重合 | 区分相关性与已证实根因 |
| 资源饱和 | CPU/内存异常、只有单一指标 | 确定性阈值；证据不足只输出候选 |

至少形成 11 个具名离线样本（前三族各 3/2/2 个、后两族各 2 个），另复用来源失败、partial、超时、取消、矛盾证据与跨 Target 隔离测试。每例存可核对的预期数值、证据归属、允许结论与禁止结论，不以固定自然语言整句为唯一断言。

### 6.2 在线模型验收

离线样本用确定性模型验证工程路径；真实模型质量单独记录。首轮选择正常、失败率异常、依赖歧义、来源缺失四例，每例最多一个父 Run，不自动重跑或挑最好结果。先复用已有烟测准入、单 Run 请求/token/期限上限，四例总上限不得超过这些既有上限之和；启动前输出整批预算供显式开启，凭据缺失直接停止。

保留现有联合验收的当次 LangSmith probe 门禁；probe 失败不能记模型验收通过。若希望将模型质量与 LangSmith 独立执行，应另记决策并修订验收契约后实施，不能在本任务顺手绕过。

通过标准：所有实际引用可回查且 scope/window 正确；关键数值与确定性结果一致；不足/歧义样本明确限制；人工逐 Run 审核 unsupported claims 为 0；终态、usage 完整性和预算检查通过。任一 not_run/review_required/failed 保留原状态，不等价于质量通过。四例通过只证明首批样本，不宣称统计准确率或全场景泛化。

## 7. S4：持久化定时巡检

首版提供固定间隔调度，最小 60 秒，时间按 UTC 存储；不引入 cron/DST 解释器。调度只接收 Target ID、受限问题模板、间隔、启停和已有记忆偏好；不得提交原始 PromQL、来源地址或动作。

建议新增版本化调度契约和 SQLite 表，最终 DDL/API 错误码在 S4 开始前记录设计决定：

- Schedule：id、targetId、revision、enabled、intervalSeconds、anchorAt、nextDueAt、lastOccurrenceId、创建/修改审计。
- Occurrence：scheduleId、scheduleRevision、dueAt、稳定 requestId、runId（可空）、状态、原因码、时间戳；`(scheduleId, scheduleRevision, dueAt)` 唯一。
- 同一 Target 同时最多一个调度产生的活跃 Run；不取消手动 Run，仍受统一顶层准入队列约束。忙碌时本次标为 skipped，不积压无界任务。
- 同一时间点重复 tick、进程重启或时钟回拨不得创建第二个 Run。持久化发生记录后，用稳定 requestId 调用 `TargetRunService.start`；在启动已接受但回填 runId 前崩溃时，重试同 requestId 并对账。
- 重启错过的多个时段合并为最多一次最新到期检查，记录跳过数量；冻结本次证据窗口，不把旧窗口默认为“现在”。不得回补全部历史任务造成风暴。
- 暂停只禁止新的 occurrence，活跃 Run 取消走既有显式操作；编辑用 expectedRevision，旧 occurrence 的窗口与配置保持不可变。
- 取消、失败或无法安全恢复的 occurrence 留下明确终态/人工处理原因。完成前不盲目释放同 Target 活跃约束；启动时对账孤儿记录。
- 单进程是运行前提；同数据目录第二宿主应拒绝启动，不能把本机制宣称为分布式锁。

## 8. S5：结果处理与站内通知

从持久化 Run 终态及报告摘要生成可恢复的本地通知。优先复用既有 durable outbox/查询能力，消费者按 Run 与通知类型去重；通知失败不修改诊断结果。

- 站内展示成功、异常、部分诊断、失败和待人工操作，不将 Run completed 当“系统健康”。诊断缺少结构化健康判定时标记待复核，禁止从自由文本猜测健康。
- 新增独立处理状态 `open | acknowledged | resolved`，与不可变原始 Run 终态、记忆审核状态分离。记录操作者、时间、原因、revision；解决状态不等于系统已恢复。
- “复查”创建同 Target 的新 Run，持久化关联旧 Run，重新采集当前证据；不改写旧报告。站内未读与处理状态分别保存。
- 导出安全 Markdown/JSON 报告，包含冻结 Target 标签、窗口、证据引用、结论、限制、规则/模型版本和复查关联；不导出原始日志、密钥、内部连接地址或私有模型上下文。
- 本阶段无外部消息发送；后续接邮件/Webhook 时增加收件人授权、可靠投递与重试边界。

## 9. S6：本地运行、数据恢复与发布

### 9.1 安装与自检

提供统一启动/停止入口，管理自身进程和本地模拟服务依赖，不终止其他进程。先检查 Node/pnpm、配置、端口、目录写权限、数据库迁移、模型配置是否完整与来源连接；失败给出稳定代码和修复指引，不输出凭据。显式区分离线演示与真实模型运行，不能缺凭据时自动换假模型。

提供最小健康/就绪查询：进程存活、核心存储就绪、配置有效、依赖降级；来源暂不可达不导致重启风暴。前端使用构建产物，提供 Linux/macOS 启动说明；Windows 至少保持既有 CI 基线，未实际验证的平台单列。

### 9.2 备份、恢复和留存

首版支持停服一致性备份；统一入口暂停新调度、结束或持久化在途状态并关闭 SQLite 后，复制数据库与其证据/blob 数据，生成版本、校验和及配置引用清单。不复制运行凭据，不把直接复制活跃 WAL 数据库称为可靠备份。

恢复先到全新显式目录，检查清单与 Schema 兼容性，再启动验证历史、证据、审核与调度对账；默认调度暂停，确认本地恢复结果后再启用。旧目录不自动覆盖，旧二进制遇到不支持的 Schema 拒绝启动。

留存清理默认 dry-run，报告候选及保护原因。保护活跃/暂停 Run、Checkpoint、待处理通知以及被保留案例或已发布知识引用的证据。若无法证明无引用则不删；明确启用清理后才执行，并记录审计。不以释放磁盘空间为由破坏证据可回查。

### 9.3 运行与发布验收

持续运行目标：两 Target、模拟来源、确定性模型、60 秒调度间隔，连续 24 小时；注入来源中断、宿主重启和备份恢复。记录硬件、版本、实际发生/跳过/完成/失败计数、RSS、数据库/证据增长、队列与时延。不用单元测试的虚拟 24 小时代替实际运行证据。

硬门槛：重复 occurrence/Run 为 0、跨 Target 泄漏为 0、未解释遗失记录为 0、悬挂超过预算且无法终结的 Run 为 0、队列不超过配置上限、恢复后引用全部可回查。资源数值作为本机容量基线报告；不凭无基线数字承诺生产 SLO。

现有 CI 已存在；补入必要的离线浏览器闭环与备份恢复检查，验证远端实际运行结果。最终发布记录提交 SHA、配置版本、迁移版本、检查结果、未验证项、回退步骤及适用边界。

## 10. 兼容性、迁移与设计门槛

- S1/S2 优先使用现有端口与持久化结构；旧 simulation、现有路由和默认记忆关闭行为不破坏。确需新增组装字段时采用可选字段及旧默认值。
- S3 新场景以新 ID/version 注册，不改变既有失败率规则或历史 Profile 语义。
- S4/S5 预计新增契约、路由与持久化表；先补详细决策、严格 Schema、错误码、事务/幂等设计和迁移测试，再实现。新表增量迁移，不删除/重命名已发布字段，不自动绑定旧 Run。
- S5 的处理状态不能复用或改变 Run、Checkpoint、记忆晋级状态。新增公开事件遵守 V2 投影与兼容测试；优先查询接口，不为 UI 随意增加事件。
- S6 清理与恢复可能影响证据可回查，实施前确认引用保护和恢复决定。回退优先关闭新功能；需要旧二进制时从停服备份恢复到另一个目录，不盲目逆向降级数据库。
- 方案中的新契约是待实施设计，不是已发布接口。本 Spec 不授权公网开放、在线费用或外部通知。

## 12. 后续对外与生产里程碑（不计入本版完成）

认证授权需覆盖用户身份、Target 访问权限、审核角色、SSE/导出权限和审计归属，再开放网络监听；不能仅修改 host。外部告警接入还需请求认证、防重放、去重及过载策略。真实业务接入须单独确认数据源、Profile、阈值和脱敏规则。真实动作须另走白名单、HITL、幂等、不确定状态核验与执行后验证。本版不会因为这些延期而虚报“生产成熟”，也不把它们强加为本地模拟开发前提。
